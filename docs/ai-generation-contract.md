# Grounded generation

Chat, administrator previews and derived knowledge use the same application-owned generation service. KodeKey, direct Google Gemini, Mistral and Groq are reviewed generation adapters. A selected model needs saved text-generation capability evidence; no provider or model fallback occurs.

Each call begins with a leased, authorized job snapshot. Local retrieval selects approved original passages from the job's project. The service reloads those originals before constructing the prompt, so supplied excerpts cannot replace source evidence. The fixed instructions take precedence over personality text, customer messages, previous replies and source text. Those values are passed as data. Private customer identifiers, connection addresses, credentials and other projects' content are excluded from conversation context.

The complete customer message remains intact, up to the existing 4,000-character chat limit. Local search uses at most 1,000 characters and 1,700 UTF-8 bytes; a longer message contributes its beginning and end to that search hint. The provider still receives the full message. History includes at most 12 recent whole messages, bounded by storage and a further 32 KiB service limit. Baseline answers select six passages from at most 20 already-authorized candidates. Exact repeated website excerpts within the same source revision have one representative; repeated short heading/summary introductions with different navigation labels are deferred behind distinct passages. Text, IDs and citation provenance are unchanged; uploaded Markdown and code-shaped excerpts keep their ranking. Unique short policies are not discarded for being short. Derived knowledge can select up to 20 source-specific passages with explicit coverage. The serialized prompt is bounded to 192 KiB, its escaped message envelope to 240 KiB, and configured output tokens remain bounded separately. Both byte checks happen before usage reservation.

Answer-only calls request native JSON mode from adapters with reviewed wire support (Gemini, Mistral and Groq). Calls advertising tools retain the native tool protocol; their tools-off final round can request JSON without discarding signed continuation. KodeKey keeps its documented request shape. This static wire-support flag does not grant observed model capabilities or authority. The prompt asks for each distinct question part, relevant qualifications and plain prose without Markdown formatting.

Each generation attempt exposes short citation handles (`S1` through `S20`) for its revalidated original passages. The same original keeps its handle through search/tool rounds; newly validated originals append handles. Model output must use exact issued handles: raw IDs, alternate spelling, duplicate or unknown handles are rejected. The service restores canonical original IDs before the existing storage recheck and commit. Support-link calls translate a copied argument for execution while preserving original model arguments and signed continuation in provider history. Handles never persist as source identifiers and never grant permission.

The model returns a strictly validated JSON object. The parser also accepts one complete, explicitly `json`-labelled Markdown fence around that object; the original response including the wrapper remains subject to the byte limit. It never extracts JSON from surrounding prose or accepts an unknown fence label. All inner schema, duplicate-key and citation checks remain identical. An answered response must cite at least one exact handle from the supplied evidence. Invalid, duplicate, foreign or invented citations are rejected. Plain answer text cannot supply its own HTML or links; the clients display separately validated source links. A lack of evidence produces a fixed, honest limitation message when tools are unavailable. Customer chat with enabled tools may still search, request a human, or prepare feedback from the customer's own content; a factual answer still requires citations. These controls verify citation provenance and constrain output; they cannot prove that every model claim follows from a citation. The release quality evaluation must test that separately.

Derived sections and FAQs retain citations to originals. Generated text is editable private material, never new factual retrieval evidence. A source-specific generation produces at most 12 entries with up to six citations each. Original passages are never clipped to fit generation; an excessive context is rejected.

Before dispatch, SQLite reserves one request and a conservative token allowance based on UTF-8 prompt bytes, framing and maximum output. This allowance is not a tokenizer or billing estimate. Provider-reported input/output counts are recorded separately. Uncertain calls retain their reservation; successful smaller calls do not refund it. Unexpected reported overages are charged. Configuration, session, source and conversation fences are rechecked before dispatch, during the call and before committing a result. Cancellation discards late output but cannot promise to cancel provider billing.

Each provider round has a 60-second outer deadline and periodic lease checks; each provider transport has its own stricter deadline. A tool-free operation makes one provider call per worker attempt. Customer chat may use the configured 1–8 tool rounds (default four), followed by at most one answer-only call, with at most eight executed tool calls across that attempt. Every round repeats context bounds, reserves its own request/token allowance, and atomically fences dispatch by job attempt and call index. Durable workers own bounded retries and final writes; a recovered attempt cannot erase previous usage or promise exactly-once provider billing. Shutdown cancels outstanding work and preserves bounded recoverable work. Provider authentication, entitlement or missing-model failures invalidate only the still-current configuration's catalogue and capabilities, disable its AI, and hand affected authorized conversations to human support. A stale denial cannot invalidate a newer configuration. No partial model response is committed or exposed as a completed message.

At the AI12 checkpoint, customer chat advertises only the five fixed tools whose individual settings are enabled. The dispatcher and SQLite independently recheck each operation's current authorization. The full tool batch is validated before any operation starts; unknown names, extra arguments, repeated call IDs, disabled tools, and more than one action in a batch are rejected. A state-changing action must be last. Report tools prepare drafts and return a fixed review acknowledgment; they never submit requests. Human handoff ends generation immediately. See [the tools and report contract](ai-tools-contract.md) for confirmation and replay behavior.

Preview and sections generation always advertise no tools and reject returned tool calls, regardless of project settings. Project AI and every tool remain off by default; explicit private previews may use provider allowance while customer AI is off. No read operation generates an answer or changes opt-ins.
